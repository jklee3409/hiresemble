CHAPTER 01

문제 정의와 개편 목표

사용자가 이 탭에 들어오는 이유는 점수를 구경하기 위해서가 아니다. 지원할지 말지를 정하고, 자기소개서에서 무엇을 강조할지를 고르기 위해서다. 현재 화면은 그 판단을 돕는 대신 같은 모양의 카드 8개를 세로로 쌓는다.

현재 화면의 구조적 문제

frontend/src/pages/JobAnalysisPage.vue 감사 결과

문제현재 상태개편 방향
카드 반복hero·overview·requirements·insights·evidence·breakdown·history가 모두 동일한 흰 카드 + 1px 테두리 + 동일 radius. 정보 중요도보다 컴포넌트 모양이 먼저 보인다.결과 전체를 단일 리포트 패널로 통합하고 내부는 1px 구분선과 여백으로만 나눈다. 카드는 “판단”과 “행동”을 묶을 때만 쓴다.
수치의 서열 부재적합도·지원 가능성·분석 커버리지가 dl 3칸에 같은 크기로 나열된다. 무엇이 결론인지 알 수 없다.적합도를 52px 히어로 숫자 + 원형 게이지로 단 하나만 지배적으로 두고, 커버리지는 같은 게이지의 내부 링으로 종속시킨다.
분포가 숫자뿐일치/일부 일치/확인되지 않음/판단 정보 부족이 개수 텍스트와 폭만 다른 무라벨 막대로 표시된다.2px 간격 + 직접 라벨 + 상태 아이콘 + 텍스처를 가진 100% 누적 막대로 바꾼다. 색을 못 봐도 읽힌다.
카테고리 점수 미해석analysis-overview__bar가 퍼센트만 채운다. 어느 영역이 약한지 비교가 안 된다.동일 기준선에 정렬된 가로 막대 차트로 5개 카테고리를 한 눈에 비교시킨다. 축은 하나만 쓴다.
이력이 목록과거 분석이 버튼 리스트로만 제공되어 “좋아지고 있는지”를 알 수 없다.analysisVersion 축의 추이 라인 차트를 넣는다. 마지막 점만 직접 라벨링한다.
CTA 경쟁‘자기소개서 준비하기’ 옆에 재분석·프로필·공고수정 링크가 같은 줄에 있고, 하단에 재분석 카드가 또 있다.결과가 있으면 primary는 자기소개서 준비하기 하나. 재분석은 리포트 헤더의 quiet 버튼으로 한 번만 노출한다.

개편 목표 — 첫 화면이 답해야 하는 4가지

1지금 어떤 상태인가 — 분석 완료 / 진행 중 / 실패 / 정보 변경됨
2결론이 무엇인가 — 적합도 점수와 지원 가능 여부, 그리고 그 점수의 한계
3왜 그런가 — 어떤 요건이 일치했고 어디가 비었는가
4다음에 무엇을 하는가 — 단 하나의 primary action
금지없는 지표 만들기(합격률·경쟁률·추천 공고), 회색조에서 읽히지 않는 색 단독 인코딩, 문장마다 카드 씌우기, primary CTA 두 개 이상.

CHAPTER 02

CHAPTER 04

자체 제작 아이콘 세트

외부 아이콘 라이브러리를 추가하지 않는다. 기존 AppIcon.vue에 아래 18개 symbol을 등록한다. 전부 24×24 그리드, stroke-width 1.8, currentColor, round cap/join으로 그렸다. 의미 없는 장식 아이콘은 하나도 없다 — 상태 4종은 색을 지워도 모양만으로 구분된다.

상태 4종 매핑 check=MATCHED · half=PARTIAL(반원 채움) · x=MISSING · question=UNKNOWN. 상태 칩·레전드·조건 행 마커에서 항상 아이콘+한글 라벨을 함께 쓴다.

CHAPTER 06

상태 모델과 화면 분기

공고를 저장하면 분석은 자동으로 이어진다. 사용자는 품질 모드를 고르지 않는다. 화면은 아래 6개 상태 중 하나를 렌더하며, 분기 우선순위가 곧 코드 순서다.

자동 분석 파이프라인

automaticAnalysis.state 전이와 각 단계에서 사용자가 보는 화면

불변실패·차단은 공고와 등록한 지원 정보를 롤백하지 않는다. 화면 문구도 항상 “저장한 정보는 그대로”를 유지한다. 진행 중 SSE 연결이 끊겨도 실패로 표시하지 않는다.

차트 4종 규격

차트데이터의 역할형태와 마크규칙

차트에서 금지하는 것

이중 축적합도와 커버리지를 한 그래프에 두 y축으로 겹치지 않는다. 게이지의 2중 링은 같은 0–100 척도를 공유하므로 이중 축이 아니다.
파이·도넛9개 조건의 4단계 상태 비교에 각도 인코딩을 쓰지 않는다. 100% 누적 막대가 항상 더 정확하다.
3D·그림자·글로우막대와 링에 입체감을 넣지 않는다. 데이터 마크에는 그림자를 쓰지 않는다.
모든 점에 숫자추이 차트에서 세 점 모두에 라벨을 붙이지 않는다. 마지막 점 하나만.
필터가 색을 재배정“일치만 보기” 필터를 눌러도 남은 항목의 색이 바뀌지 않는다. 색은 상태에 고정되며 순서에 따르지 않는다.

완화 지점적용 범위근거
결정 히어로 배경 blob우상단 1곳, radial-gradient, 최대 alpha 0.13, pointer-events:none사용자가 지정한 토스 레퍼런스의 핵심 시각 장치. 리포트에서 “결론 영역”을 한 번에 찾게 하는 기능을 한다. 텍스트 대비에 영향을 주지 않는 강도로 제한했다.
추이 차트 면 채움라인 아래 #3157ff 0.14 → 0 세로 그라디언트라인 차트의 표준 관례이며 값 읽기를 방해하지 않는다. 데이터 마크(라인·점) 자체는 단색이다.
이 문서를 반영할 때 위 두 예외의 근거는 docs/design/progress.md의 Session Summary와 이 문서에 남긴다. .superdesign/design-system.md가 저장소에 존재하는 동안에는 같은 예외를 그 문서에도 함께 명시한다. 문서와 구현이 어긋난 채로 두지 않는다.
